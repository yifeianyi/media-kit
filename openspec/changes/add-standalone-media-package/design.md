# Design

## Context

目标目录是全新项目，现有文件仅为本次初始化的 OpenSpec。动机与范围见 `proposal.md`；本设计不依赖参考项目的工作目录、数据库、环境变量或服务进程。

只读调研确认以下复用起点，路径相对于参考项目 `../._give_up_New_xxm_fans_home/apps/api/`：

| 参考材料 | 已观察到的行为 | 新包的处理 |
| --- | --- | --- |
| `app/integrations/thumbnails/{models,converter}.py` | 标准库与 Pillow；EXIF 定向、首帧、等比缩放、原子 WebP 写入 | 复用处理契约，调整路径与结果类型，单独转换无需存储实例 |
| `app/modules/media_assets/thumbnails.py` | 登记与入队可同事务；内容 hash、任务 token、删除 generation 保护发布 | 保留可靠性机制；以资产身份、不可变 revision 与删除状态隔离旧任务 |
| 同上任务去重和复用查询 | 配置版本进入任务键，但未完整进入派生物复用与 URL 身份 | 新包统一使用不可变配方快照与完整指纹 |
| `repository.py`、`storage.py`、`app/db/sqlite.py` | 查询业务表、固定目录特例、媒体初始化顺带创建业务表 | 自行设计仓储与 schema，业务知识全部留在接入项目 |
| `tests/core/test_thumbnails.py`、`tests/integration/test_thumbnail_tasks.py` | 方向、透明、动画、资源限制、并发领取、租约恢复、部分失败、过期发布验证 | 移植行为测试，去除 `app.*` 与业务表夹具 |
| `docs/backend/media.md`、媒体静态服务 | API、worker、静态服务使用同一媒体根，API 停止后文件仍可读 | 提供单实例配置及可独立使用的静态服务示例 |

用户已确认：其他项目以 Python 为主；采用新媒体目录并交由包完整托管；源码公开并允许修改；文档随包交付供开发者和 agent 调阅。参考项目无需使用新包。Python 3.11+、MIT、默认三档 WebP 和下列 API 命名属于本提案的初始工程默认值。

## Goals / Non-Goals

**Goals:**

- 以本地文件系统和包自管 SQLite 提供可恢复的单机托管；导入模块无文件、数据库或进程副作用。
- 让调用者使用稳定资产身份与逻辑路径，避免依赖物理文件结构或内部 SQL。
- 通过不可变版本、同事务入队和发布校验，把原图提交、缩略图处理及其失败分别表达。
- 保持模块和测试可直接阅读、修改、独立构建；通过单个发行版本管理源码、文档和 CLI。

**Non-Goals:**

- 不建立通用分布式队列、插件市场或任意文件管理器；首版扩展边界服务于已有三种实现。
- 不承诺文件系统与 SQLite、宿主业务数据库形成共同事务；不依据包内引用计数自动清理业务资产。
- 不把版本文件当作可供业务回滚的备份产品；备份仍需包含同一时点的媒体和状态数据。

## Decisions

### 1. 一个发行包，内部按职责分层

采用 `src/media_kit/` 布局：`api.py`、`models.py`、`errors.py`、`config.py`、`storage/`、`transforms/`、`tasks/`、`persistence/`、`cli.py`。运行时依赖以 Pillow 为核心，SQLite、TOML 读取和命令行解析使用标准库；不引入 Web 框架、ORM、Redis 或 Celery。

`storage` 提供文件安装、隔离和地址坐标；`transforms` 接受本地输入与明确输出位置，不查询数据库；`persistence` 管理包自身表和事务；`tasks` 组合它们完成处理；`api` 返回稳定类型对象。只在这些边界定义小型协议与契约测试，使用者可替换实现或 fork 修改。Python 直接转换接口无需创建 store、初始化数据库或运行 worker。

选择一个包而非多个独立发行物，减少初版版本协调；选择本地实现而非远程服务，符合已确认的 Python 接入与独立目录托管需求。

### 2. 显式初始化，配置与存储实例绑定

配置可由 Python 类型对象或 TOML 提供。`MediaStore.init(config)` 创建空媒体目录及状态目录，`MediaStore.open(config)` 打开已存在实例。`open` 不建表、不自动迁移 schema；它在支持的现有格式上恢复已记录的中断操作后提供服务。只读检查使用独立只读入口，不能为了检查先调用会恢复写入的 `open`。

默认配置草案：

```toml
[storage]
root = "/data/example/media"
original_dir = "src"
variant_dir = "thu"
state_dir = "/var/lib/example/media"

[thumbnails]
sizes = [320, 640, 1280]
format = "webp"
quality = 80
method = 4
max_pixels = 40000000
max_bytes = 20971520
algorithm_version = "webp-v1"

[urls]
original_base = "/media/src/"
variant_base = "/media/thu/"
```

`root`、`state_dir` 必须为显式绝对路径且互不嵌套；原图/变体目录为 root 内非空相对目录，彼此不能重叠或嵌套。媒体标记与状态数据库记录相同 `store_id`、布局版本、schema 版本和目录配置。已有非空未知目录、实例标识不匹配或布局配置漂移均报明确错误，不创建第二套数据。重复初始化仅在同一实例与相同配置时幂等。

原图、变体和 root 内私有安装/隔离区必须在同一本地文件系统，初始化/open 校验实际文件系统与路径边界；状态目录可位于其他文件系统。目录不通过符号链接逃出 root。布局固定后，首版不提供自动搬迁；URL 前缀可以修改，因为 URL 从当前配置与存储坐标计算，不作为资产身份持久化。

### 3. 稳定身份、逻辑 key 与不可变版本

资产 ID 使用随机 UUID，删除后不复用。`key` 是可选的规范 POSIX 相对逻辑路径，供唯一约束、前缀列表和业务定位使用；未提供时由包分配。key 不直接决定磁盘位置，规范化不得把多个歧义输入静默合并；拒绝绝对路径、空段、`.`、`..`、反斜杠、NUL 等无效输入。文件名扩展名与实际解码格式不匹配时拒绝，保存不会隐式转码原图。

默认物理布局：

```text
<root>/
  .media-kit.json
  src/<asset_id>/<revision>/<filename>
  thu/<asset_id>/<revision>/<recipe_fingerprint>/<profile>.webp
  .media-kit-private/
    staging/<operation_id>/
    quarantine/<operation_id>/

<state_dir>/
  store.json
  media.sqlite3
```

原图 revision 为单资产递增整数；每次显式替换成功产生新 revision，即使内容相同也具有明确的并发更新身份。保存保留源字节和格式，hash 用于完整性验证，不自动合并相同内容的业务资产。逻辑 key 在活动、安装中或删除中的资产间唯一；资产完成删除后才允许新资产重新使用同一 key。

选择不可变版本文件而非原地覆盖，避免旧任务读取到半次替换或缓存地址继续对应不同内容。代价是磁盘占用增加；重建/替换时将过期产物记为可回收，显式维护操作可清理已经失去当前指向的版本，失败或无人使用不能自行推断为可回收。

### 4. 公共 Python API 与结果对象

以下是实现应遵循的接口形状；具体类型签名在 API 文档与契约测试中同步维护：

| 入口 | 主要语义 |
| --- | --- |
| `MediaStore.init(config)` / `open(config)` | 初始化或打开受管实例 |
| `save(source, *, key=None, idempotency_key=None)` | 接收路径或二进制流，复制输入，完整安装原图后登记资产和任务；源文件不移动 |
| `get(asset_id)` / `list(prefix=None, page=1, page_size=30)` | 查询元数据；返回明确的总数、分页和状态 |
| `resolve(asset_id, *, profiles=None)` / `resolve_many(asset_ids, ...)` | 返回当前 revision 的原图、所选已请求档位与状态；批量不要求调用方逐条查询 |
| `replace(asset_id, source, *, expected_revision, idempotency_key=None)` | 版本匹配后安装新 revision，保持资产身份和逻辑 key |
| `rebuild(asset_id, *, profiles=None)` | 为当前 revision 显式请求当前配置中的新配方，或补齐同配方缺失档位 |
| `retry(asset_id)` | 重试当前 revision/当前请求下失败档位，保持原参数快照 |
| `process(asset_id, *, timeout=None)` | 调用同一持久任务执行器并等待；返回处理状态，超时不撤销原图 |
| `delete(asset_id, *, expected_revision, idempotency_key=None)` | 开始并推进删除，返回明确的删除进度；同一资产重复删除幂等 |
| 独立转换函数 | 输入原图和转换配置，生成结果；无 store、数据库和 worker 要求 |

`AssetView` 至少包含资产 ID、逻辑 key、当前 revision、资产状态、原图的存储坐标/可选 URL/MIME/尺寸/字节数/hash，以及每档位的配方指纹、状态和已发布结果。省略 URL 配置时仍可使用坐标和本地存储接口。批量解析对每个请求 ID 返回结果或明确缺失状态；删除中的资产不返回可使用的文件地址。

`resolve` 默认使用该 revision 每个 profile 最新显式提交的请求；修改配置本身不改变历史资产的默认请求，也不会触发查询写入。显式 profile 筛选是已请求档位的子集，未知名称报错。`rebuild(profiles=[...])` 只原子更新选中档位，其他档位保持原请求；省略 profiles 时请求当前配置的全部档位，已有但已不在配置中的档位保留，首版不提供隐式删除档位。后续解析不会回退到被切换的旧配方或旧 revision 的缩略图。已被替换的历史请求可查询，但 `retry(asset_id)` 只针对当前 revision 的当前档位请求，不重新激活历史请求。

每档状态为 `pending/running/ready/failed`。聚合状态：全部就绪为 `ready`；存在未完成任务为 `pending/processing`；任务均终止且部分成功为 `partial`、全部失败为 `failed`。原图已提交独立表达，不根据转换状态撤销保存成功。

错误类型区分配置、实例不兼容、输入校验、逻辑 key 冲突、并发版本冲突、幂等冲突、资产缺失、存储故障和处理故障，避免只返回无法判断能否重试的通用异常。

### 5. 原图安装、SQLite 提交和幂等

SQLite 表围绕 `assets`、`revisions`、`variant_requests`、`variants`、`tasks`、`operations`、`idempotency_records` 组织；不存业务表名、业务权限或外部数据库连接。

保存/替换先在私有 staging 校验输入与 hash，再持久化操作意图、目标资产/预期 revision、目标路径与内容校验信息。通过同文件系统原子安装完整版本文件后，在一个 SQLite 事务中提交资产当前指向、revision、配方请求、待处理任务与幂等结果。成功返回以原图已完整安装、数据库提交完成为条件。

文件与 SQLite 不能共同提交，因此 `operations` 保留恢复所需阶段和决策。启动恢复根据已提交决策完成安装或隔离未提交产物；替换最终提交再次比较预期 revision。所有变更与恢复共用每资产/逻辑 key 的串行操作协议，不依赖单进程内存锁。参考实现的文件日志/回滚经验可借鉴，但不能复制其业务恢复入口。

幂等记录的作用域为同一 store 的操作类型与幂等键；请求摘要覆盖目标、预期 revision、输入内容 hash 和转换快照。同键同请求返回既有结果或继续同一操作；同键不同请求在修改前冲突。重放判断先于当前 revision 检查，因此已经成功的替换不会因其版本递增而误报冲突。重放原先成功的 save 不复活已删除资产，而是返回原操作结果、原资产身份及可辨别的当前状态。

包的资产提交与任务提交原子；宿主业务记录默认使用独立事务。文档示例演示“先保存资产、再写业务关联；关联失败保留资产并重试或显式删除”，不提供虚假的跨库原子承诺，也不自动清理未关联的资产。

### 6. 转换配方与发布身份

默认档位 320/640/1280，WebP quality=80、method=4；最长边等比缩放，不裁剪、不放大，EXIF 定向，透明度保留，动画使用首帧。JPEG/PNG/GIF/WebP 为默认输入集合，AVIF 在运行环境具备解码能力时接受；解码能力不足须在输入校验或显式能力检查中报告，不能先宣布保存成功再发现无法识别格式。字节和像素限制在完整解码/转换前检查，并捕获解压缩炸弹告警。

配方快照包含档位尺寸、输出格式、质量、编码方法、方向/动画/缩放策略和 `algorithm_version`，按规范化 JSON 计算 SHA-256 指纹。任务和派生记录保留完整快照与完整指纹；输出路径、任务去重、复用判断和 URL 使用同一身份。资源配额作为执行校验记录，不替代影响输出的配方参数。

每档直接从不可变原图生成。转换函数写临时结果，托管运行器在发布前检查资产 active、当前 revision、当前档位请求及领取 token；然后原子发布完整文件并登记变体。fork 修改算法时必须更新算法版本并运行契约测试；仅修改源码而不更新算法身份无法可靠识别缓存失效，文档明确这项维护责任。

选择参数快照而非 worker 当前全局配置，确保配置修改后旧任务仍执行原来的请求。重试保持快照；新配方由 `rebuild` 明确创建。相同身份已有有效文件可复用，缺失档位补生成。

### 7. 单机持久任务与统一执行路径

每个 profile 使用独立持久任务，去重身份包含 store、资产 ID、revision、profile 名称和配方指纹。同参数不同名称的 profile 可以共享配方指纹，但必须分别产生其结果与状态。通过带条件的 SQLite 写事务领取，设置随机 claim token、尝试次数和租约；默认租约 300 秒、心跳 30 秒。到期允许重新领取；旧领取者即使完成计算也不能发布。独立 worker 以查询可领取任务的方式处理，避免先加载整个历史任务表；首版单进程串行执行图片，支持多个本机 worker 竞争领取。

转换在 SQLite 写事务之外执行。心跳续租使用短事务，发布前在写事务内复核领取权、当前版本和该 profile 当前请求的指纹。重建切换当前请求时，被取代的任务终止为 superseded，或由同等可查询原因表达；即使仍是相同 revision，旧配方也不能重新成为当前结果。处理保证是可重复执行与单一有效发布，不承诺计算严格只运行一次。

同步 `process` 通过与 store 绑定且并发受限的本地执行上下文驱动同一持久任务执行器，不另写绕过登记的同步分支；其他 worker 已领取时等待其结果。`timeout` 约束调用方等待期限：转换不能直接占据等待线程，达到期限后调用可返回 timed_out 与资产/请求当前状态，即使单档解码尚未结束；原执行上下文继续处理，或在进程退出后由租约恢复。实例显式关闭时按文档终止接收新工作并处理在途上下文，不能因一次超时创建无限多执行器。阻塞转换测试必须证明独立于转换完成的超时返回，而非只在档位间检查期限。部分失败保留成功档位；显式 `retry` 或 `rebuild` 重新安排失败/缺失任务。首版不默认无限自动重试失败任务；CLI 和错误文档给出恢复命令。

### 8. 删除完成意味着源站公开文件已移除

资产公开状态为 `active -> deleting -> deleted`。删除先持久化不可逆的撤销决策，检查预期 revision，取消待执行任务并阻止新发布；解析立即停止返回该资产地址。之后按 SQLite 登记且尚未回收的具体原图/变体文件生成持久清单，逐文件原子移入同文件系统私有隔离区，仅移除空父目录并保留相邻未知文件。所有受管 revision 均已移出公开目录后，才记录 `deleted`。失败保留 `deleting` 和错误/待办，重试或启动恢复识别自己的隔离目标后继续推进；源与隔离目标冲突或两处均缺失不会伪报完成。

历史回收遵守相同文件登记边界，清理已被替换的 revision 和配方，不承担业务备份职责。已回收记录不再拥有该公开路径，后续出现的同路径文件不得自动复用或删除。回收待办失败时暂停该资产的冲突写操作，防止重新启用的配方被旧回收意图删除；其他资产继续工作。损坏变体重试保留文件登记，直到重新发布或隔离成功。

隔离区物理销毁使用独立 `pending/complete/failed` 清理状态，允许后台重试。重复删除或已删除对象返回同一删除结果。新的资产即使复用逻辑 key，也使用新 ID，因此旧任务不能命中新文件。

`deleting` 期间，已知静态 URL 在对应文件被移走前仍可能访问；`deleted` 只保证源站受管路径不可读，不能撤回浏览器/CDN 已缓存的字节。业务引用检查和撤销外部授权由宿主负责。这比只更新元数据的删除承诺更符合静态服务的真实行为。

### 9. CLI、静态服务和维护

CLI 提供 `init`、`worker`、`status`、`check`、`recover`、`retry`、`rebuild`、`cleanup`、`docs --path`；worker 支持 `--once` 与持续运行，`status` 查询资产和任务。CLI 与 Python API 使用同一配置、错误模型和运行器，提供可解析结果与正确退出码。`check` 与 `status` 默认只读，恢复/重建/清理必须显式调用相应命令。

静态示例仅映射配置中的原图、缩略图目录，不公开整个 root、state_dir 或私有安装区；URL helper 逐段编码文件坐标。不可变版本 URL 可使用长期缓存，删除与敏感数据的缓存策略由部署文档明确。API 停止后已发布图片仍由静态服务读取。v0.1 面向本地磁盘，网络文件系统和多主机并发不列入保证。

备份指南要求停止写入，或使用等效一致快照，配套保存媒体根与状态目录；恢复到新环境后先核对 store ID/格式版本并执行只读检查。schema 迁移必须显式执行、先备份，不能在普通导入或打开中发生。首版交付从空实例开始；布局升级工具仅在实际引入新格式时提供，不为尚不存在的历史格式编造迁移逻辑。

### 10. 开源发行与文档同源

采用标准 `pyproject.toml`、src 布局、类型标注及 `py.typed`，构建 wheel/sdist。文档在仓库 `docs/` 维护唯一权威正文；构建时将同版本内容作为包资源带入 wheel，sdist 同时包含源码、测试、示例和文档。通过包资源读取与 CLI 定位离线文档，不要求安装后返回原仓库或联网。README 为发行页与文档导航入口。

文档最小集合：quickstart、configuration、API、storage-and-lifecycle、integration、operations、upgrading、development、customization、agent-guide。纯 Python 示例覆盖保存、后台/同步处理、查询、替换、重试和删除；框架集成说明给出通用接入边界，不引入框架运行依赖。所有文档记录成功后置条件、冲突副作用、重试与崩溃恢复语义。

公开 API 文档必须逐一覆盖包入口 `__all__` 中的公开导出：函数/方法说明输入、输出、错误、重试与成功后状态，结果类型说明字段语义；独立转换的能力查询与结果类型（如 `format_capabilities`、`TransformResult`）以及配置和文档工具入口不得只在实现中存在。发行检查在 wheel 与 sdist 上校验同一离线资源集合（含中英文 README），验收脚本所要求的前置工具（如 `uv`）必须在开发文档中声明。

根 `AGENTS.md` 说明修改本包的目录归属、构建/验证命令与存储格式约束；`docs/agent-guide.md` 面向消费方提供按任务阅读入口，链接权威正文。customization 提供可执行的配置修改和转换算法版本修改案例；开发者可 editable 安装，修改后通过测试重建发行物。

## Risks / Trade-offs

- [文件与数据库无法共同提交] → 持久操作意图、不可变文件、明确提交决策及故障注入恢复测试；不把原子文件替换描述为跨介质 ACID。
- [SQLite 与本地文件限制吞吐和部署拓扑] → 定义单机支持边界、短事务和按条件领取；后续适配保留小型协议，不提前加入分布式依赖。
- [不可变版本和隔离区占用空间] → 记录过期版本与清理状态，提供显式维护与磁盘故障诊断；清理不推断外部业务引用。
- [使用者绕过包手动修改文件] → 文档说明托管写入入口，check 报告 hash/文件差异，默认不静默采纳外部改动。
- [fork 后改变算法或 schema 未更新版本] → 区分包版本、磁盘/schema 版本、算法版本，提供修改示例、测试及显式迁移边界。
- [离线文档与源码漂移] → 文档同源打包，在发行物安装环境执行关键文档示例并检查文档资源完整性。
