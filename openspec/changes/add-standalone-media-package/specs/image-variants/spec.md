# Spec Delta

## Purpose

提供可预测且可独立使用的图片校验与派生图转换行为，让接入项目在保留原图的同时获得按配方管理的缩略图，并在配置改变、内容替换或部分失败时准确识别可用结果。

## ADDED Requirements

### Requirement: 基于实际图片内容校验输入

系统 MUST 根据实际可解码内容识别图片格式和尺寸，并拒绝损坏、格式不受支持或超出配置字节与像素限制的输入。格式能力 SHALL 可查询；声明格式或文件扩展名与实际内容冲突时必须报错，不通过隐式重编码掩盖冲突。

#### Scenario: 拒绝伪装图片
- **WHEN** 输入带有图片扩展名但内容不是有效图片
- **THEN** 系统返回可识别的输入校验错误，不提交资产或转换任务

#### Scenario: 拒绝超限图片
- **WHEN** 图片文件大小或解码尺寸超过已配置的限制
- **THEN** 系统拒绝处理并说明触发的限制，不发布不完整派生图

### Requirement: 默认缩略图遵循固定视觉规则

系统 SHALL 默认提供最长边分别为 320、640、1280 像素的 WebP 配方，质量为 80、编码 method 为 4。每档必须直接从原图解码，按 EXIF 定向、保持比例、不放大小图、保留透明度，并对动画使用首帧。

#### Scenario: 方向和比例正确
- **WHEN** 为带 EXIF 方向信息的图片生成默认缩略图
- **THEN** 输出符合可见方向，保持原比例，最长边不超过对应档位且尺寸不超过定向后的原图

#### Scenario: 透明动画输入
- **WHEN** 为具有透明度的动画图片生成默认缩略图
- **THEN** 每档输出使用首帧的定向画面并保留透明度，原始动画文件保持不变

### Requirement: 调用方能够配置并校验转换配方

系统 SHALL 允许调用方以具名 profile 配置缩略图尺寸、WebP 质量和编码参数；profile 名称必须唯一且适用于安全路径。非法尺寸、参数范围或重复名称 MUST 在请求被接受前返回配置错误，不产生无法执行的持久任务。

#### Scenario: 使用自定义缩略图档位
- **WHEN** 调用方配置有效的自定义最长边、质量和编码参数
- **THEN** 新转换请求按这些参数生成并返回对应 profile 的结果

#### Scenario: 配方配置无效
- **WHEN** profile 名称重复、包含路径穿越或参数越界
- **THEN** 系统拒绝配置且不登记新转换任务

### Requirement: 配方快照和指纹不可变

系统 MUST 为每个转换请求保存不可变配方快照，并由影响输出的参数及转换算法版本生成确定性指纹。同一快照产生相同指纹；相关参数或算法版本变化必须产生不同指纹。已提交任务不得因运行时配置变化而改用另一配方。

#### Scenario: 入队后配置改变
- **WHEN** 一个请求已按质量 80 入队，随后运行时配置改为质量 90
- **THEN** 原请求继续使用质量 80 的快照，新的请求使用不同指纹，不混用两者结果

### Requirement: 转换保护原图和既有结果

系统 MUST 在保存及转换全过程保留原始图片字节，不将缩略图写回原图。每档转换应独立生成完整输出后再发布；某档失败不得破坏其他已成功档位或改变原图内容指纹。

#### Scenario: 一个档位转换失败
- **WHEN** 多档转换中一个档位失败而其他档位已成功
- **THEN** 成功档位继续可用，失败档位单独报告，原图字节及内容指纹保持不变

### Requirement: 派生解析严格匹配版本与配方

系统 SHALL 仅将与资产当前 revision、所请求 profile 和配方指纹同时匹配的已就绪派生物作为有效结果。缺失或未完成时 MUST 返回明确状态，并可单独返回当前原图地址；不得将旧 revision 或不同指纹的图片伪装为匹配的缩略图。

#### Scenario: 原图替换后等待新缩略图
- **WHEN** 原图已替换而新 revision 的对应 profile 尚未就绪
- **THEN** 系统表达派生物未就绪，并提供当前原图信息，不返回旧 revision 的缩略图作为成功结果

#### Scenario: 同名 profile 配方已变化
- **WHEN** 同名 profile 的新配方指纹尚无就绪结果，但旧指纹已有文件
- **THEN** 解析新配方时仍返回未就绪，不复用旧指纹结果

### Requirement: 重试保持原配方而重建可使用新配方

系统 SHALL 在当前 revision 的当前失败请求重试时使用其原始配方快照，保留有效成功档位；已被取代的历史请求仅可查询，不因重试重新成为当前。新参数必须通过明确重建请求应用；选择部分 profile 时只更新这些档位，未选档位保持原请求，旧指纹和历史结果不被改写。

#### Scenario: 修改配置后重试旧失败任务
- **WHEN** 调用方改变默认配方但尚未重建，随后重试仍为当前请求的失败档位
- **THEN** 系统继续按该历史请求的快照处理缺失档位，不以当前默认配置替换它

#### Scenario: 只重建指定档位
- **WHEN** 调用方仅选择一个 profile 提交新配方重建
- **THEN** 该 profile 切换为新请求，其他 profile 的当前配方、结果和状态保持不变

### Requirement: 独立转换无需存储与数据库

发行包 SHALL 提供直接图片转换入口，允许调用方指定输入、输出目标和配方，在无需初始化受管存储、元数据库或 worker 的情况下执行同样的图片处理规则。独立入口 MUST 保留输入文件，不创建受管资产或任务，也不得以输出目标覆盖输入文件。

#### Scenario: 纯文件转换
- **WHEN** 调用方仅提供有效输入图片、独立输出目标和配方调用转换入口
- **THEN** 系统生成对应图片结果与元信息，不建立数据库、资产目录或后台任务
