# Spec Delta

## Purpose

定义受管图片从创建、查询、替换到删除的公开行为，使其他 Python 项目可以依靠稳定身份、版本检查和可恢复操作接入媒体能力，并准确处理业务数据库、文件系统及缩略图状态之间的边界。

## ADDED Requirements

### Requirement: 资产身份与内容版本稳定

系统 SHALL 为每个新资产分配稳定 asset_id，分别记录逻辑 key、当前 revision、内容指纹和生命周期状态。状态 MUST 明确区分 active、deleting、deleted；成功替换保留 asset_id 并递增 revision，已提交版本的文件内容不得原地修改。

#### Scenario: 替换保持资产身份
- **WHEN** 一个 active 资产完成内容替换
- **THEN** 系统返回相同 asset_id、增加后的 revision 和新内容指纹，旧版本内容不会被原地覆盖

#### Scenario: 删除后重新使用逻辑路径
- **WHEN** 一个资产已完成删除，调用方重新使用其逻辑 key 创建图片
- **THEN** 系统创建不同 asset_id，旧资产身份和旧任务不得被复活

### Requirement: 保存复制原图且默认不覆盖

系统 SHALL 接受本地图片文件或二进制输入，将通过校验的原始字节复制到受管存储，创建 revision 1 的资产并返回身份和转换状态。提供 key 时 MUST 拒绝与 active 或 deleting 资产重复的 key；保存不得移动、删除或改写调用方的源文件。

#### Scenario: 保存外部输入
- **WHEN** 调用方使用一个有效外部图片文件创建新资产
- **THEN** 受管原图与输入字节一致，外部文件保持不变，结果包含 asset_id、key、revision 和缩略图状态

#### Scenario: 逻辑路径冲突
- **WHEN** 保存请求使用了一个仍被 active 或 deleting 资产占用的 key
- **THEN** 系统返回冲突，不替换既有图片、不创建另一个同 key 的资产

### Requirement: 查询与批量解析表达当前可用状态

系统 SHALL 提供分页资产查询和按资产身份批量解析，并返回原图信息、当前 revision、生命周期及所请求派生图的就绪状态。批量结果 MUST 对应输入顺序并逐项表达不存在或不可用；deleting、deleted 资产不得解析成可用媒体，不得以旧 revision 的派生图掩盖当前结果缺失。

#### Scenario: 批量包含不存在资产
- **WHEN** 调用方一次解析有效资产、不存在的资产及 deleting 资产
- **THEN** 系统按输入顺序分别返回当前媒体结果、不存在结果和不可用结果，其他有效项仍可使用

#### Scenario: 分页读取存量资产
- **WHEN** 调用方在没有并发修改的情况下连续读取资产列表的分页结果
- **THEN** 系统按声明的稳定排序返回结果，分页之间不会遗漏或重复同一资产

### Requirement: 替换要求预期版本一致

系统 MUST 在替换前验证资产处于 active 且 expected_revision 等于当前 revision。成功替换 SHALL 创建新的不可变原图版本、原子切换当前版本并登记新转换任务；冲突或校验失败不得改变当前版本，旧版本的任务结果不得成为新版本的媒体结果。

#### Scenario: 并发替换冲突
- **WHEN** 两个请求都基于同一 expected_revision 替换同一个资产
- **THEN** 至多一个请求成功递增版本，另一个收到版本冲突并保留已提交的新版本

#### Scenario: 替换输入无效
- **WHEN** 替换请求的图片校验未通过
- **THEN** 系统保持原 asset_id、revision、当前原图及已就绪派生图不变

### Requirement: 可选幂等键防止重复变更

系统 SHALL 为保存、替换和删除接受可选幂等键，并在同一存储及操作范围内绑定请求身份、输入内容指纹和相关参数。同键同请求 MUST 复用原操作及结果，不重复创建资产或版本；同键不同请求 MUST 返回冲突。重放判断应先于会使原成功请求失效的当前版本检查。

#### Scenario: 保存响应丢失后重试
- **WHEN** 保存已经提交但调用方未收到响应，随后以同一幂等键、相同内容和参数重试
- **THEN** 系统返回原保存结果及同一 asset_id，不新增副本

#### Scenario: 替换成功后重放
- **WHEN** 成功替换后调用方重放同一幂等键和原 expected_revision 的相同请求
- **THEN** 系统返回原替换结果，不因当前 revision 已递增而将该重放误报为新的版本冲突

#### Scenario: 幂等键被用于不同输入
- **WHEN** 调用方以已使用的幂等键提交不同图片内容或操作参数
- **THEN** 系统返回幂等冲突且不执行新的变更

### Requirement: 删除完成以受管文件退出公开目录为准

系统 MUST 在匹配 expected_revision 后持久记录删除决定，将资产置为 deleting 并撤销后续解析及派生发布。只有该资产全部受管版本的原图和派生物已移出公开目录时，状态才能成为 deleted；文件操作失败 SHALL 保持 deleting 并支持重试。私有隔离区清理结果必须独立表达。

#### Scenario: 删除包含历史版本
- **WHEN** 删除一个具有多个原图版本和派生图的资产且操作成功
- **THEN** 所有受管版本的公开文件均被移走或删除，资产为 deleted，旧任务无法重新发布这些文件

#### Scenario: 删除途中发生文件错误
- **WHEN** 删除决定已提交但部分公开文件无法移除
- **THEN** 资产保持 deleting，系统报告未完成项并允许重试，不报告 deleted

#### Scenario: 缓存仍保存已删除内容
- **WHEN** 源站公开文件已移除，但外部浏览器或 CDN 仍保存旧响应
- **THEN** 删除结果只声明受管源站文件已移除，不声明已经撤回外部缓存内容

### Requirement: 中断文件操作可恢复到明确结果

系统 MUST 为跨文件与元数据的保存、替换和删除维护可恢复操作记录。重新打开存储或执行恢复时 SHALL 按已持久化的提交决定完成或回退操作，使资产记录和文件达成一致；恢复必须可重复执行，且不得覆盖后来已提交的内容版本。

#### Scenario: 文件安装后进程中断
- **WHEN** 进程在文件安装与元数据操作完成之间中断，随后重新打开存储
- **THEN** 系统识别该操作并恢复至一致结果，无法安全恢复时明确报告并阻止相关冲突变更

#### Scenario: 重复执行恢复
- **WHEN** 同一中断操作已经恢复完成后再次执行恢复
- **THEN** 系统不重复创建资产、递增版本或覆盖后续内容

### Requirement: 原图成功与转换失败分别表达

系统 SHALL 将已提交原图的可用状态与缩略图的 pending、running、成功或失败状态分开返回。转换失败或同步等待超时 MUST 保留已成功保存的原图和资产身份，并提供继续查询或重试所需的任务信息，不将其描述为整个保存未发生。

#### Scenario: 原图成功而转换失败
- **WHEN** 原图已提交，后台某个缩略图转换失败
- **THEN** 原图仍可解析使用，结果明确表达转换失败并允许针对未完成派生物重试

### Requirement: 宿主业务引用与事务由宿主管理

系统 SHALL 独立管理自身媒体事务，不声称能与外部业务数据库共同原子提交。宿主负责授权、业务引用及删除前的引用检查；系统 MUST 保留尚未关联宿主业务记录的资产，不因缺少内部业务引用自动删除它们。

#### Scenario: 保存后业务事务失败
- **WHEN** 媒体保存成功但宿主后续保存文章记录的事务失败
- **THEN** 媒体资产仍然存在并可查询或显式删除，系统不会声称两个事务共同回滚
