# Spec Delta

## Purpose

让媒体转换请求在独立进程、同步等待和进程中断之间保持一致的执行语义，保证已登记任务不会因调用进程退出而丢失，并避免并发处理、图片替换或删除导致过期派生图被重新发布。

## ADDED Requirements

### Requirement: 转换任务随原图登记持久提交

系统 MUST 将正式原图版本的元数据与其请求的转换任务在同一个包内元数据事务中提交。只有已正式登记的原图才能产生可执行任务；无 worker 时任务 SHALL 保持可查询的待执行状态，不影响已提交原图的解析。

#### Scenario: 没有运行 worker
- **WHEN** 调用方成功保存图片但没有启动 worker
- **THEN** 原图可用且转换任务保持待执行，重新打开存储后任务仍然存在

#### Scenario: 保存事务回滚
- **WHEN** 正式原图登记未能提交
- **THEN** 不存在可被 worker 领取的对应转换任务，文件按操作恢复契约处理

### Requirement: 重复转换请求复用同一处理身份

系统 SHALL 根据资产身份、原图 revision、profile 名称、内容指纹和不可变配方快照识别相同转换请求。重复提交相同请求 MUST 复用已有请求及有效结果，不重复创建并发处理；不同 profile、revision 或配方指纹必须分别识别。

#### Scenario: 重复请求相同缩略图
- **WHEN** 两个调用方为同一资产版本和同一配方请求缩略图
- **THEN** 系统返回同一处理身份或其已有结果，不形成两套竞争发布的独立任务

#### Scenario: 同配方的不同具名档位
- **WHEN** 两个不同名称的 profile 使用相同尺寸和编码参数
- **THEN** 两个 profile 均具有可查询的处理身份和对应就绪结果，不因配方指纹相同而遗漏其中一个

### Requirement: 任务领取具有租约和所有者标记

系统 MUST 原子领取可执行任务，为每次领取生成独立所有者标记和有限租约，并防止有效租约内的重复领取。租约到期后 SHALL 允许重新领取；旧所有者不得继续提交任务状态或发布输出。

#### Scenario: 两个 worker 竞争同一任务
- **WHEN** 两个 worker 同时尝试领取一个待执行任务
- **THEN** 仅一个获得有效领取权，另一个不会处理该任务的同一次租约

#### Scenario: worker 中断后接管
- **WHEN** 持有任务的 worker 中断且租约到期
- **THEN** 另一个 worker 可以使用新的所有者标记继续处理，旧标记失去提交权限

### Requirement: 派生发布前重新验证资产和任务有效性

系统 MUST 在正式发布每档派生图及其元数据前重新验证任务所有者、资产仍为 active、当前 revision、原图内容指纹，以及该 profile 的当前请求和配方指纹均匹配任务快照。任何条件不满足时必须拒绝发布，清理或隔离未发布输出，并记录可识别的过期原因。

#### Scenario: 转换期间替换原图
- **WHEN** worker 转换期间资产已被成功替换为新 revision
- **THEN** 旧任务的后续发布被拒绝，不覆盖或冒充新 revision 的结果

#### Scenario: 转换期间提交删除
- **WHEN** worker 完成转换前资产已进入 deleting
- **THEN** worker 不能将输出写回公开媒体位置，删除后的任务也不能恢复该资产

#### Scenario: 同版本重建切换配方
- **WHEN** worker 转换期间，同一 revision 的该 profile 已显式切换为新配方请求
- **THEN** 旧任务不能发布为当前结果，并以已被取代或等效终止原因区分于普通转换失败

### Requirement: 分档失败可定位和重试

系统 SHALL 独立记录各 profile 的状态、错误和有效输出，失败时保留成功档位。重试必须沿用原配方快照，并复用经校验仍有效的结果；只针对缺失、损坏或失败档位继续处理，不撤销原图。

#### Scenario: 重试部分成功请求
- **WHEN** 一个请求已有两个有效成功档位和一个失败档位，调用方请求重试
- **THEN** 系统保持成功结果并处理失败档位，最终结果仍属于原 revision 和原配方快照

### Requirement: 同步等待使用持久任务执行语义

系统 SHALL 提供同步等待转换结果的方式，并与独立 worker 使用相同的持久任务、领取校验、转换快照和发布规则。等待期限 MUST 独立于单档转换完成；超时返回已保存资产和当前状态，不回滚原图或删除任务，执行上下文或后续 worker 可以继续同一请求。

#### Scenario: 同步等待超时
- **WHEN** 原图保存成功后同步等待超过调用方指定期限
- **THEN** 调用方得到资产身份、当前任务信息和超时状态，任务保持可继续执行

#### Scenario: 单档转换阻塞超过等待期限
- **WHEN** 本地执行的单档转换仍在运行，且等待期限已到达
- **THEN** 等待调用能够在转换结束前返回超时与资产状态，后续可以查询该请求的完成或租约恢复结果

#### Scenario: 同步调用与 worker 同时执行
- **WHEN** 同步等待调用和独立 worker 同时接触同一请求
- **THEN** 两者遵守相同租约规则，最终只接受拥有有效领取权的发布结果

### Requirement: worker 可单次或持续独立运行

系统 SHALL 提供不依赖 Web 应用生命周期的独立 worker，支持单次处理和持续处理模式。worker 必须使用明确指定的存储配置；停止或中断不得把未完成任务误报为成功，未完成租约可由后续运行恢复。

#### Scenario: 单次处理空队列
- **WHEN** 以单次模式启动 worker 且没有可执行任务
- **THEN** worker 正常退出并明确报告未领取任务，不长时间保持空闲运行

#### Scenario: 重启持续 worker
- **WHEN** 持续 worker 在处理途中中断并于之后重新启动
- **THEN** 已完成档位保持有效，未完成任务按租约和恢复规则继续处理

### Requirement: 任务状态及错误可观测

系统 SHALL 提供按请求或资产查询任务状态的入口，返回任务身份、源 revision、配方指纹、尝试次数、各档结果和可识别的错误信息。失败、等待、租约执行中及已过期结果必须可区分，错误不得只存在于进程日志中。

#### Scenario: 查询历史失败任务
- **WHEN** 调用方在 worker 进程已退出后查询失败任务
- **THEN** 系统仍能返回持久化错误、失败档位、源版本和重试所需身份
