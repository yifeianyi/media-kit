# Proposal

## Why

多个 Python 项目需要一致的图片保存、目录组织和缩略图处理能力，而现有参考实现混合了 FastAPI、业务数据库、日封面和历史路径规则。建立独立开源包，可将已验证的图片处理与故障恢复机制交付给其他开发者和 agent，并允许使用者修改源码、测试和重新打包。

## What Changes

- 在独立项目 `/home/yifeianyi/Desktop/media-kit` 建立框架无关的 Python 包；分发名暂定 `media-kit`、导入名 `media_kit`、命令名 `media-kit`。参考项目仅作为调研来源，不要求其安装或改造。
- 对新建媒体目录提供完整托管：显式初始化、可配置原图/缩略图目录、逻辑路径、资产身份、不可变原图版本、访问地址解析及包自管 SQLite 元数据。
- 提供保存、分页查询、批量解析、带版本检查的替换、幂等请求、删除、文件核对与中断恢复；项目业务引用和授权由接入项目管理。
- 提供 Pillow 图片转换，默认生成 320/640/1280 像素 WebP，并保留原图；转换参数快照及算法版本参与派生图指纹。
- 提供持久任务、独立 worker、租约和发布校验；同步等待与 worker 执行相同任务路径，原图可用状态与缩略图状态分别表达。
- 提供标准 wheel/sdist、类型信息、命令行、可运行示例，以及随发行物交付的人类和 agent 离线文档、源码修改指南、测试及许可声明。
- 首版聚焦本地单机图片存储。已有目录接管、参考项目迁移、视频转码、对象存储、集中媒体服务、管理 UI、业务图册、跨项目共享资产及外部业务数据库共同事务不在本次范围。

## Capabilities

### New Capabilities

- `managed-media-storage`: 新媒体存储初始化、配置、安全目录边界、逻辑路径、文件发布和静态访问映射。
- `media-asset-lifecycle`: 资产与版本、保存/查询/替换/删除、幂等、业务事务边界和可恢复文件操作。
- `image-variants`: 图片校验、可配置缩略图、转换指纹、原图保护和版本匹配的派生结果。
- `media-task-runtime`: 持久化入队、任务领取、租约、重试、同步等待及拒绝过期结果。
- `media-package-distribution`: 框架无关 Python API、CLI、标准发行物、类型信息、可修改源码和构建验证。
- `media-package-documentation`: 随包离线文档、完整接入示例、操作语义、二次开发与 agent 导航及示例验证。

### Modified Capabilities

无。目标项目为新建项目，没有既有能力需要修改。

## Impact

- 新增目标项目中的 `src/media_kit/`、测试、示例、文档、构建配置及开发自动检查；这些是后续实施产物，本次仅创建规划文件。
- 运行时以 Python 3.11+、Pillow 和标准库 SQLite 为基线，不依赖 FastAPI、Flask、Django 或参考项目的 `app.*`。
- 参考材料包括原项目的 `app/integrations/thumbnails/`、媒体任务/屏障/文件安装机制及其测试；包需要自行设计 schema 和接口，不带入业务表、固定 URL 或 `Source/CloudePhotos` 特例。
- 新包独立管理磁盘格式和 schema 版本。初始许可按 MIT 规划，实施时核实所复用文件的权属与署名；本次不授权对外发布到任何注册表或创建远程仓库。
- 发布验收以干净环境安装 wheel/sdist，执行完整托管流程、故障恢复场景、离线文档读取及源码修改后重新打包为依据。
